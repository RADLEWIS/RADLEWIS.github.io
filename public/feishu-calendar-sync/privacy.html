Privacy policy

Feishu Calendar Sync · Effective November 9, 2026

Operator and purpose

RADLEWIS operates Feishu Calendar Sync as a personal integration between the operator's own Feishu and Google accounts. Data is used solely to copy and maintain calendar events from Feishu in a dedicated Google calendar.

Data accessed

The utility reads Feishu CalDAV event data, including event identifiers, titles, start and end times, recurrence rules, descriptions, locations, and cancellation information. It uses a Google OAuth access token and refresh token to create and manage an application-created calendar.

Within that Google calendar, it reads copied events and synchronization metadata to identify duplicates and changes. It writes event titles, times, descriptions, and locations, plus identifiers and content hashes used for synchronization. Descriptions may contain meeting links or other information entered in the source event. Attendee lists, invitation responses, and attachments are not copied as separate fields. Gmail messages are not accessed.

Data use and sharing

Copied event information is sent to Google Calendar at the owner's request. Feishu and Google process requests under their respective policies. The utility does not sell calendar data, use it for advertising, share it with other application users, or use it to train AI models. There is no public data collection endpoint on this website.

Feishu Calendar Sync's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

Storage and security

The utility runs on the owner's server. CalDAV credentials and Google OAuth tokens are stored in files with access restricted to the owner's server account. Requests to Feishu and Google use HTTPS. Operational logs record synchronization timestamps, event counts, and results; the application does not intentionally log credentials, event titles, or descriptions. Copied events and synchronization metadata are stored in the dedicated Google calendar.

Retention and removal

Credentials remain on the owner's server until the owner removes them. Copied events remain in Google Calendar until the utility removes them following source changes within its synchronization window, or the owner deletes them. Previously copied historical events outside the synchronization window are retained.

The owner can stop the server's synchronization timer, revoke the application's access in Google Account connections, remove the credential files, and delete the dedicated Google calendar. Revoking access alone does not delete events already copied into Google Calendar.

This website

These information pages do not set analytics cookies or contain tracking scripts. GitHub Pages hosts the website and may record visitors' IP addresses for security purposes, as described in the GitHub Privacy Statement.

Contact and changes

For questions about this application or its data practices, contact the developer through the public RADLEWIS GitHub profile. Changes to this policy will be published on this page with an updated effective date.
